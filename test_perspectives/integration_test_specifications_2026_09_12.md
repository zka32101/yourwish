| KPI | 目標値 | 測定方法 |
|---|---|---|
| 対局開始までの時間 | < 30秒 | マッチング開始→ゲーム開始 |
| 盤面更新遅延 | < 200ms | RTDB ストリーム応答時間 |
| 対局中クラッシュ率 | 0% | logcat 監視 |
| チート検出スコア | < 50点 | Firestore cheat_analysis |

### Scenario 3️⃣: 報告・ブロック機能フロー

#### テストフロー

```
1. 不正プレイヤー報告
   ├─ 対局終了後、相手プロフィール画面表示
   ├─ 「報告」ボタンをタップ
   ├─ 報告理由選択（ソフト指し / 遅延行為 / etc）
   ├─ 報告コメント入力
   ├─ 送信
   └─ Firestore reports コレクションに記録 ✅

2. ブロック機能
   ├─ 同じ相手をブロック ✅
   ├─ Firestore users/{uid}/blocked_users に追加 ✅
   └─ 次のマッチメイキングでブロック対象を除外 ✅

3. 自動BAN検証（スパム報告検出）
   ├─ 同一ユーザーへ3件以上報告 → 報告者BAN
   ├─ 報告数10件以上で却下率80%以上 → 報告者BAN
   └─ 被報告者報告数10件達成 → 被報告者BAN

4. 通知確認
   ├─ BAN通知がメール送信される ✅
   └─ Firestore notifications に記録 ✅
```

## 📝 **共通統合テストチェックリスト**

### Firebase 統合テスト

```
□ Firebase 初期化成功（ログに "Firebase initialized"）
□ Firestore へのデータ書き込み成功
□ Realtime Database リアルタイム同期
□ Authentication ユーザーセッション
□ Crashlytics エラーレポート送信
□ FCM プッシュ通知受信
□ Cloud Functions トリガー実行
□ タイムアウト処理（30秒以上応答なし → 自動敗北）
```

### パフォーマンステスト

```
□ アプリ起動時間 < 3秒
□ ホーム画面ロード < 2秒
□ バトル1ターン処理 < 1秒
□ メモリ使用量 < 500MB
□ バッテリー消費 < 10%/分（低速プレイ時）
□ ネットワーク帯域幅 < 1MB/分（通常プレイ）
```

### セキュリティテスト

```
□ チート検出スコア < 50点（正常プレイ）
□ 不正報告スパムフィルター動作
□ ブロック機能による除外確認
□ 課金領収書検証（サーバー側）
□ BAN システム自動実行
□ データ暗号化（Firestore Rules）
```

### エラーハンドリングテスト

```
□ ネットワーク切断 → 自動復帰
□ サーバー遅延（> 5秒） → タイムアウト処理
□ 無効なカード選択 → エラーメッセージ
□ メモリ不足 → グレースフルシャットダウン
□ クラッシュ時 → Crashlytics で自動報告
```
