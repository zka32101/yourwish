# アプリ調査観点チェックリスト(子ども向け Flutter アプリ共通)

小学コレ系など、子ども向け・課金あり・Firebase利用アプリの調査で、アプリごとに同じ基準で確認するための観点集。
調査はアプリ単位でセッションを分けて行う(コンテキスト節約)。結果は下の表に ✅/⚠️/❌ で記録する。

> このリポジトリは Public。実際のキー・パスワード・IDの値は書かないこと(「有無」「場所」だけ記録する)。

## 1. シークレット・設定
- [ ] ソース/ワークフロー/ドキュメントにパスワード・APIキー・秘密鍵の直書きがない(`git log -p` の履歴も含む)
- [ ] CI のシークレットは `secrets.*` 参照。ワークフロー内にプレースホルダ(例: プロジェクト番号)が残っていない
- [ ] keystore / `key.properties` / `google-services.json` / `.env` がコミットされていない
- [ ] 漏洩の疑いがあれば、ローテーションと履歴削除の要否を判断

## 2. Firestore / バックエンド
- [ ] ルールは `request.auth != null` と uid 一致で最小権限
- [ ] 検証用の `allow write` が、無条件の `allow` と別行(OR評価)で無効化されていない
- [ ] 公開パス(`/public/**` 等)の書き込みが制限されている(匿名認証でも書けないか)
- [ ] 最後に `match /{document=**}` で全拒否
- [ ] Firebase API キーのアプリ制限(Android/iOS)と App Check
- [ ] 課金の権利判定をサーバー側(RevenueCat webhook等)でも検証している

## 3. Android / iOS ビルド・署名
- [ ] release が debug 署名にフォールバックしない(CIで `key.properties` 欠落時は失敗)
- [ ] `targetSdk` が Play の要件を満たす / `minSdk` が妥当
- [ ] `android:allowBackup` の方針(購入状態・学習記録の扱い)
- [ ] 不要な権限がない。マイク等は用途・送信有無をポリシーと申告に明記、拒否時のフォールバックあり
- [ ] `build/` など生成物がコミットされていない

## 4. 子ども向け規制(Google Play ファミリー / Apple Kids)
- [ ] 保護者ゲートが購入・外部リンク・設定・アカウント系・広告タップに適用されている
- [ ] ゲートが子どもに解きにくい(単純な足し算でない)、失敗回数のロックアウトがある
- [ ] AdMob: 子ども向け指定(`tagForChildDirectedTreatment` / `tagForUnderAgeOfConsent`)と最大広告レーティング
- [ ] 広告IDが未設定のダミー値のまま残っていない
- [ ] Analytics / Crashlytics: 広告ID・IDFA取得の無効化、同意と収集の最小化
- [ ] プライバシーポリシー、ストアのデータ安全性申告と実装が一致

## 5. 課金
- [ ] 購入前の保護者ゲート(復元は対象外でよい)
- [ ] 購入・復元・失敗・キャンセルのエラー処理
- [ ] 権利状態の改ざん耐性(クライアント判定のみでない)

## 6. リポジトリ衛生
- [ ] 不自然なパス(文字化け・クォート付き)や誤コミットがない
- [ ] `.gitignore` が生成物・秘密ファイルを網羅
- [ ] アプリ間でキー/IDの使い回しがないか整理
